An n8n workflow that reads a 50,000-record BMW sales dataset from Google Sheets, validates each row, builds a Region + Year KPI table, asks an LLM for a schema-checked summary, and emails an HTML report through Gmail. Each run is also logged to a separate History tab.

> **Status:** tested with manual runs. The workflow includes a Schedule Trigger for recurring runs, but this repo doesn't claim a production schedule.

## Sample output

The file [`sample_output/weekly_summary_sample.html`](sample_output/weekly_summary_sample.html) is the email body from a test run on the 2010–2024 dataset. It contains:

- Date range, total revenue ($19,012,242,534,459), and rejected rows (0)
- Three insights, each traced to a single Region + Year row
- A recommended action with a target region, year, and value
- The full KPI table: 6 regions × 15 years = 90 rows

## How it works

```
Schedule / Manual Trigger
  → Google Sheets Read (data tab)
  → Validate Data        (valid rows → output 0, rejects → output 1)
  → Aggregate KPI Table  (totals, units, and simple average price per Region + Year)
  → AI Summary LLM       (OpenAI, JSON output, temperature 0)
  → Parse & Fallback     (JSON parse + schema check; falls back to "insufficient data")
  → Build Email          (Code node: builds HTML from the KPI table)
  → Send Gmail           (HTML body, attribution off)

Parse & Fallback → Google Sheets Log (History tab, one row per run)
```

## Design decisions

- **Validation before aggregation.** Rows with missing fields or non-numeric revenue, units, or price are routed to a reject output and counted, instead of silently skewing totals.
- **LLM for wording, not arithmetic.** The model receives the computed KPI table and must copy numbers from it. Every value in the output is checked against the table.
- **Schema check with fallback.** If the LLM response isn't valid JSON or doesn't match the expected structure, the workflow sends the report with the KPI table and a clear "insufficient data" message, rather than failing silently.
- **Separate log tab.** Run summaries are written to a History tab, so they can't be read back in as sales records.

## Verification

- Total revenue was checked by parsing all 50,000 records from the source PDF: $19,012,242,534,459.
- Each record's `Total_Revenue` equals `Price_USD × Sales_Volume`.
- Highest-revenue row: Europe 2022 ($235,580,072,926). Lowest: North America 2012 ($180,204,716,918). Highest average listed price: North America 2015 ($77,465.06).
- Repeat runs on the same data produced identical totals.

## Setup

1. **Google Sheets:** create a data tab named `Sheet1` with the columns `Model`, `Year`, `Region`, `Price_USD`, `Sales_Volume`, and `Revenue`. Create a second tab named `History`.
2. **Import the workflow:** in n8n, choose **Import from File** and select `workflow/bmw_sales_kpi_report.json`.
3. **Credentials:** connect Google Sheets, OpenAI, and Gmail. Replace the placeholders `YOUR_SHEET_ID` and `you@example.com`.
4. **Test:** run the workflow manually. Check that the email total matches the sum of the KPI table's revenue column.
5. **Schedule:** set the Schedule Trigger interval to the frequency you want.

## Known limitations

- Sample data is a 50,000-row export, not a live feed. Each run uses whatever is in the data tab.
- "Average price" is a simple average of listed prices, not revenue-weighted.
- The recommended action is generated by the LLM from a validated table. Treat it as a suggestion to investigate, not a verified business decision.
- The Build Email code builds the table from the data, so changing the number of regions or years needs no code change.
